# KKarea — standalone Revit 2023 add-in for Area Calc

**Date:** 2026-07-06
**Status:** Approved

## Goal

Ship the Area Calc (Rishui Zamin area submission) tool to Revit 2023 users as a
separate add-in named **KKarea**, without bringing Revit 2023 back into RVTuk
itself. RVTuk continues to target Revit 2024/2025 only; KKarea targets Revit
2023 only.

## Background

RVTuk supported Revit 2023 until commit `7ff0383` dropped it (the blocking
UNC/SQLite problem was `System.Data.SQLite`'s, since fixed by switching every
config to `Microsoft.Data.Sqlite`). Revit 2023 hosts .NET Framework add-ins, so
it builds against `net48` exactly like the Release2024 config. The known API
gaps in the Area Calc slice are:

- `ElementId.Value` (long) exists in Revit 2024+; Revit 2023 uses
  `ElementId.IntegerValue` (`AreaExtractor.cs`, `Raw()` helper).
- `new ElementId(long)` exists in Revit 2024+; Revit 2023 only has
  `new ElementId(int)` (`SelectAreaEventHandler.cs`).

Any further 2023-incompatible API in the slice surfaces as a compile error and
gets the same `#if REVIT2023` treatment.

## Architecture

### New project: `src\KKarea.Revit\KKarea.Revit.csproj`

- `net48`, `PlatformTarget` x64, `UseWPF`, nullable enabled — mirroring
  RVTuk.Revit's net48 shape.
- Packages: `Nice3point.Revit.Api.RevitAPI` / `RevitAPIUI` pinned `2023.*`,
  compile-only (`ExcludeAssets="runtime"`), same as RVTuk.Revit's pattern.
- `DefineConstants`: `REVIT2023`.
- Project references: `RVTuk.Core`, `RVTuk.UI`. It must **not** reference
  `RVTuk.Revit` (different Revit API versions).
- Output: `bin\2023\Release2023\`.
- Built only under the new `Release2023` solution configuration.

### Shared source by link (single-source, compiled per host)

Linked as `<Compile Include="..\RVTuk.Revit\...">` items so the logic stays
single-source and each host compiles it against its own Revit API version:

- `AreaSubmission\AreaExtractor.cs`
- `AreaSubmission\UsageKeyScheduleBuilder.cs`
- `ExternalEvents\AreaExtractEventHandler.cs`
- `ExternalEvents\SelectAreaEventHandler.cs`
- `ExternalEvents\SetupUsageKeysEventHandler.cs`
- `Commands\SetupRishuiZaminParamsCommand.cs` + the `RZ_AreaParams.txt`
  content item, **if** the workflow still needs the command (verify during
  implementation; the window's `SetupUsageKeys` handler may have subsumed it —
  if so, leave it out of KKarea).

The linked files keep their `RVTuk.Revit.*` namespaces inside the KKarea
assembly; that is acceptable. They gain `#if REVIT2023` shims (dead code in
RVTuk's own builds):

- `AreaExtractor.Raw()`: `id.IntegerValue` under `REVIT2023`, `id.Value`
  otherwise.
- `SelectAreaEventHandler`: `new ElementId((int)ElementId)` under `REVIT2023`.

### KKarea's own host glue (new files, adapted from RVTuk.Revit)

- `Application.cs` — `IExternalApplication`; registers the three external
  events (`AreaExtract`, `SelectArea`, `SetupUsageKeys`), installs the
  assembly-resolve hook and crash logging (same pattern as RVTuk; crash log
  can share `%LOCALAPPDATA%\RVTuk\crash.log`), and creates one ribbon panel
  "KKarea" with a single "Area Calc" push button reusing the existing
  `CreateAreaCalcIcon` drawing code.
- `AreaCalcCommand.cs` — adapted copy of RVTuk's command: wires
  extract/select/export/setupUsageKeys delegates into the shared
  `AreaSubmissionViewModel` + `AreaSubmissionWindow` from RVTuk.UI, using
  KKarea's own `Application` statics. Single-instance window behavior kept.

### RVTuk.Core / RVTuk.UI: add `Release2023`

- Both csproj files gain a `Release2023` property group: `net48`, output
  `bin\2023\Release2023\`, constant `REVIT2023`.
- The `#if REVIT2024` gates that actually mean "net48" become
  `#if NETFRAMEWORK` (auto-defined on net48): `Config/ConfigManager.cs`,
  `Serialization/SnapshotJson.cs`, `Database/SqliteNative.cs`,
  `AreaSubmission/UsageCatalog.cs`.
- The csproj package/reference ItemGroup conditions keyed on
  `'$(Configuration)'=='Release2024'` become
  `'$(TargetFramework)'=='net48'` (and the net8 groups the inverse) so
  Release2023 lands in the net48 branch (`Microsoft.Data.Sqlite`, GAC
  `System.Drawing`, no `System.Text.Json`).
- Net effect: zero behavior change for Release2024/Release2025.

### Solution

- Add `KKarea.Revit` to `RVTuk.sln`.
- Add a `Release2023` solution configuration mapping: Core, UI, KKarea.Revit
  build; `RVTuk.Revit` and `RVTuk.Core.Tests` do **not** build under it.
- Under Release2024/Release2025, `KKarea.Revit` does **not** build.

## Add-in identity

- Entry class: `KKarea.Revit.Application`.
- ClientId: a **new** GUID, generated once at implementation time and kept
  stable forever after (same rule as RVTuk's).
- Vendor ID: `KnafoKlimor`.
- Manifest: `KKarea.addin`, generated by `Deploy.ps1`.

## Deployment

`Deploy.ps1` gains a 2023 entry alongside 2024/2025:

- 2023 → build `KKarea.Revit` with `-c Release2023`, deploy flat to
  `C:\ProgramData\Autodesk\Revit\Addins\2023\KKarea\`, generate
  `KKarea.addin`.
- Same per-version resilience: skip with a warning if Revit 2023 is open
  (DLLs locked) or build output is missing; other years proceed.
- Same net48 post-processing as 2024: strip the BCL polyfill DLLs Revit
  preloads; copy `e_sqlite3.dll` flat (Core references
  `Microsoft.Data.Sqlite` even though Area Calc doesn't open a DB — shipping
  the same closure keeps the deploy logic uniform and safe).
- RVTuk's 2024/2025 deploys are unchanged.

## Error handling

Same patterns as RVTuk, via the shared/adapted code: extractor errors surface
through `AreaExtractEventHandler.Error` and are rethrown to the view model;
command-level failures append to the crash log and show a TaskDialog; ribbon
creation failures show a TaskDialog at startup.

## Testing & verification

1. `dotnet build RVTuk.sln -c Release2023` — new config builds Core, UI,
   KKarea.Revit.
2. `dotnet build RVTuk.sln -c Release2024` and `-c Release2025` — must stay
   green (proves the `NETFRAMEWORK` gate rename and csproj condition changes
   are behavior-neutral).
3. Existing Core test suite passes.
4. `.\Deploy.ps1 2023` deploys KKarea; manual smoke test in Revit 2023:
   open a sheet with area plans, run Area Calc, extract, select-in-model,
   usage-key setup, export DXF+DAT.

## Out of scope

- Any other RVTuk tool on Revit 2023 (Family Browser, Comparator, Neo
  Properties, Auto Dimensions).
- Trimming unused windows/views out of the RVTuk.UI assembly that KKarea
  ships (dead weight, harmless).
- A Release2023 config for `RVTuk.Revit` (explicitly not added).
